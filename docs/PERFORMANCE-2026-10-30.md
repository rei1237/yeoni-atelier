# 로딩 성능 검증 · 2026-10-30

## 변경
- 처음 카페에서 바로 사용하는 직원·손님과 소품·아이콘은 준비하고, 그 밖의 동료 의상·대화용 이미지·초상화는 해당 장면에서 요청한다. 해상도, WebP 원본, 모바일 3배 캔버스와 고해상도 그림 선택 기준은 그대로다.
- 사냥 출발과 사냥 중 저장 이어하기는 선택한 사냥꾼과 적 이미지 준비를 기다린다. 불러오지 못하면 출발이나 이어하기를 완료하지 않고 재시도 안내를 표시한다.
- 메뉴 아이콘의 실제 등록 크기는 대체로 96~160px이며, 최근 상위 메뉴 아이콘은 128px·약 9~11KB다. 파일 손실 압축과 해상도 축소의 추가 이득이 작아 변경하지 않았다.

## 전후 측정
동일한 로컬 서버와 Chrome 자동화, 390×844 CSS px·DPR 3, CPU 4배 느리게, 왕복 지연 40ms와 다운로드 1.5MiB/s 제한, 빈 브라우저 캐시, 각 1회. 로딩 화면이 닫힐 때까지 CDP 완료 요청의 전송량 합계다. 측정치는 비교용이며 실제 휴대전화나 운영 네트워크 성능을 뜻하지 않는다.

| 로딩 화면 종료 | 10.85초 | 6.09초 |
| 전체 완료 요청 | 462건 | 358건 |
| 완료 이미지 요청 | 258건 | 154건 |

테스트에서는 새 게임 도입 후 준비 화면과 사냥 중 저장의 이어하기를 열었다. 이어하기는 일시정지를 보존하고 네오·공격·보스 이미지가 준비된 것을 확인했다. 모바일·데스크톱 실제 기기에서 프레임 속도와 메모리, 모든 후반 동료·화면과 느린 네트워크 복구는 별도 확인이 필요하다.

## 카페 영업 중 화면 처리 추가 검증
- 카페 화면이 바뀌지 않은 HTML 하위 트리는 다시 순회하지 않는다. 말풍선 크기는 매 프레임 한 번만 읽고, 좌표가 달라진 경우만 스타일을 갱신한다. 기본 방 그림을 쓰는 상태에서는 화면에 그리지 않을 바닥 셀 순회를 건너뛴다.
- 같은 시드 42, 3명·주문 9건으로 시작하는 개발용 영업 화면, 390×844 CSS px·DPR 3·CPU 4배 감속 Chrome에서 7초씩 한 번 비교했다. 스크립트 실행 시간은 1.91초→1.73초, 총 작업 시간은 3.34초→3.08초, 33.4ms를 넘긴 프레임 간격은 6회→5회였다. 실측 환경과 상태에 따라 달라지는 단일 실험이며 모든 기기에서의 개선률을 보장하지 않는다.
- 같은 시각과 상태로 기본 준비·영업·확장·편집 캔버스를 비교해 네 화면 모두 픽셀 차이가 없었다. DOM 갱신 시 펼친 메뉴, 입력값·포커스, 캔버스 내용이 유지되고 바뀐 텍스트가 갱신되는 것도 확인했다. 실제 휴대전화의 장시간 영업과 최대 확장에 따른 성능은 별도 확인한다.

## 카페 경제 계산 추가 검증
- 메뉴 선택에서 성장 레벨을 한 번 읽고 각 메뉴 가중치를 한 번만 계산한다. 손님 부유도 가중치도 성장과 분위기를 각각 한 번만 계산한다. 분위기 합계는 같은 중복 가구 규칙을 유지하면서 불필요한 중간 배열을 만들지 않는다. 가격·난수 호출 수·선택 순서와 저장 데이터를 변경하지 않는다.
- Node.js 로컬 벤치마크, 가구 61개·팁 장부 3,000건, 각 함수 2,000회, 동일 시드·조건의 단일 실험: 메뉴 선택 10,139ms→447ms, 부유도 가중치 1,281ms→486ms, 분위기 5ms→4ms. 장부가 길어진 상황을 만든 계산 실험이며 휴대폰 프레임이나 일반 사용자 체감 속도를 뜻하지 않는다.
- 기준 구현과 여러 성장 단계, 손님 종류, 재고·인연 및 난수 시드를 비교해 메뉴 선택과 난수 상태가 일치함을 확인했다. 실제 게임의 장기간 수동 플레이 성능은 별도 확인한다.
